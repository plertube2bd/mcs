## 머리말

이 문서는 MC# 프로그램이 **무엇을 의미하는지**를 정합니다. 튜토리얼과 가이드는 사용법을 설명하고, 이 문서는 "이렇게 쓰면 정확히 무엇이 일어나는가"에 답합니다. 생성된 `.mcfunction`을 직접 읽지 않아도 프로그램의 동작을 예측할 수 있게 하는 것이 목적입니다.

이 문서의 규칙 중 관찰 가능한 동작에 관한 것은 테스트로 확인됩니다. 규칙 번호와 그 규칙을 검사하는 테스트 파일의 대응은 [부속서 E](#부속서-e-참고-규칙과-테스트의-대응)에 있습니다. 문서와 구현이 다르면 결함이며, 어느 쪽이 틀렸는지 판단해 고칩니다.

---

## 1 적용 범위

1.1 이 문서는 다음을 정합니다.

- MC# 소스 프로그램의 형식과 번역 과정 (6절)
- 값의 표현과 연산의 결과 (7절, 8절)
- 저장소, 이름, 수명 (9절)
- 실행 순서와 실행 맥락 (10절)
- 문장, 클래스와 객체, 컴파일 타임 평가의 의미 (11–13절)
- 버전 대응, 진단, 구현 한계 (14–16절)

1.2 이 문서는 다음을 정하지 **않습니다**.

- 내장 라이브러리 각 멤버의 시그니처. [API 레퍼런스](../api.md)가 컴파일러 선언에서 자동 생성되며, 그것이 규정입니다.
- 생성되는 명령의 구체적인 형태. 같은 의미라면 구현은 다른 명령을 낼 수 있습니다. 단, 9.2에서 "안정"으로 표시한 이름은 예외입니다.
- Minecraft 자체의 동작 (블록 갱신, 엔티티 AI 등).

## 2 인용 규격

- **C# 언어 명세** (ECMA-334) 및 Roslyn 구현: 구문과 타입 검사는 C#을 따릅니다. 이 문서는 C#과 **다른 점**만 적습니다.
- **Minecraft Java Edition 명령어**: 각 대상 버전의 바닐라 명령어 동작.

## 3 용어와 정의

**3.1 구현** — 이 문서가 대상으로 하는 컴파일러 `mcs`.

**3.2 대상 버전 범위** — 빌드에 지정한 Minecraft 버전 범위 (`--mc`, `mcs.json`의 `"minecraft"`).

**3.3 버전 층** — 팩 포맷이 같고 생성 결과가 같은 대상 버전의 묶음. 데이터팩의 기본 층 또는 오버레이 하나가 됩니다.

**3.4 스코어 홀더** — 스코어보드 objective 안의 이름 하나 (`$main.sum`, `@s`, `Steve`).

**3.5 소유 홀더** — 구현이 직접 만들고 쓰는 홀더. 이름이 `$`로 시작하거나 `#<정수>` 꼴입니다.

**3.6 외부 스코어** — 소유 홀더가 아닌 스코어. 엔티티·플레이어의 스코어(`[Score]` 필드, `Objective[...]`)와 `m.Mount`로 연결한 스코어가 여기에 속합니다.

**3.7 미설정 스코어** — 홀더가 objective 안에 값을 갖고 있지 않은 상태.

**3.8 실행 맥락** — 명령이 실행되는 실행 주체(`@s`), 위치, 회전, 차원의 묶음.

**3.9 컴파일 타임 상수** — 다음 중 하나:
  (a) C# 상수식 (리터럴, `const`, 상수끼리의 연산),
  (b) 상수 인자로 바인딩된 `[Inline]` 매개변수, `Unroll.Range`와 테이블 `foreach`의 반복 변수,
  (c) (a)–(b)만으로 이루어져 명령을 하나도 내지 않고 계산되는 식.

**3.10 런타임 값** — 컴파일 타임 상수가 아닌 값.

**3.11 매크로 줄** — 실행 시점에 값을 끼워 넣는 함수 매크로 명령 (`$say $(a0)`). 1.20.2 이상에서만 존재합니다.

**3.12 로드** — 데이터팩이 활성화될 때: 월드를 열 때, 그리고 `/reload`할 때마다.

**3.13 진단** — 구현이 출력하는 오류(error) 또는 경고(warning).

**3.14 동작 키워드** — 이 문서의 "~해야 한다(shall)"는 요구, "~하지 않아야 한다(shall not)"는 금지, "~하는 것이 좋다(should)"는 권고, "~할 수 있다(may)"는 허용입니다.

**3.15 지정되지 않음** — 구현이 여러 결과 중 하나를 낼 수 있고, 어떤 것인지 문서화하지 않는 경우. 프로그램은 특정 결과에 의존하지 않아야 합니다.

## 4 적합성

4.1 **적합 프로그램**은 대상 버전 범위의 모든 버전에서 오류 진단 없이 번역되는 프로그램입니다.

4.2 **적합 구현**은 적합 프로그램에 대해, 대상 범위의 모든 버전에서 이 문서가 정한 관찰 가능한 동작을 내는 데이터팩을 만들어야 합니다. 관찰 가능한 동작은 다음과 같습니다.
  - 스코어와 스토리지의 값 (9.2의 안정 이름)
  - 채팅 출력과 그 순서
  - 실행되는 월드 명령(`summon`, `setblock`, `playsound` 등)과 그 순서·실행 맥락

4.3 구현은 이 문서가 표현할 수 없다고 정한 구성(예: 1.20.1에서 런타임 값을 명령에 끼우기)에 대해 오류 진단을 내야 하고, 그때는 데이터팩을 만들지 않아야 합니다.

---

## 5 표기

- 코드는 `고정폭`으로 씁니다. `<ns>`는 데이터팩 네임스페이스, `<m>`은 메서드 이름의 snake_case입니다.
- "→"는 "다음으로 번역된다" 또는 "결과는"을 뜻합니다.
- 규칙 번호(예: **8.3.2**)는 테스트와 이슈에서 인용하는 데 씁니다.

## 6 프로그램 구조와 번역

### 6.1 소스 파일

6.1.1 소스 파일은 확장자가 `.mcs`인 UTF-8 텍스트입니다.

6.1.2 여러 파일은 하나의 프로그램으로 번역됩니다. 파일의 순서는 다음과 같습니다.
  - 명령줄: 주어진 순서
  - `mcs.json`의 `"sources"`: 항목 순서대로, 폴더와 패턴 안에서는 경로의 서수(ordinal) 정렬 순서

  이 순서는 10.1의 `[Load]`, 10.3의 `[Tick]` 실행 순서를 정합니다.

### 6.2 전처리

6.2.1 다음 MC# 구문은 C#으로 바뀐 뒤 타입 검사를 받습니다 (`--emit-csharp`로 결과를 볼 수 있습니다).

| MC# | 같은 뜻의 C# |
|---|---|
| `use X;` | `using X;` |
| `new T : K x;` | `T x = new T(TType.K);` |
| `asm 명령;` / `asm { … }` | 명령 한 줄 / 여러 줄 |
| 최상위 메서드·필드 | 클래스 `__Global`의 정적 멤버 |

6.2.2 모든 파일의 최상위 멤버는 **같은** `__Global` 클래스에 들어갑니다. 따라서 두 파일에 같은 이름의 최상위 필드가 있으면 C# 오류(CS0102)입니다. 이름이 조용히 합쳐지는 일은 없습니다.

### 6.3 타입 검사

6.3.1 구문과 타입 규칙은 C#을 따릅니다. 위반은 `CSxxxx` 코드가 붙은 오류 진단입니다.

6.3.2 C#에서 유효하더라도 이 문서가 정하지 않은 구성은 `MCS` 오류 진단을 받아야 합니다. 조용히 다른 의미로 번역되어서는 안 됩니다.

### 6.4 코드 생성과 버전 층

6.4.1 프로그램은 대상 범위 안의 팩 포맷 그룹마다 따로 번역됩니다. 결과가 같은 그룹은 하나의 층으로 합쳐집니다 (14절).

6.4.2 한 층에서라도 오류가 나면 빌드 전체가 실패합니다. 오류 메시지 앞에는 해당 버전이 붙습니다 (`[1.20.1] …`).

## 7 타입과 값의 표현

### 7.1 숫자와 불리언

| 타입 | 저장 | 값의 범위 | 단위 |
|---|---|---|---|
| `int` | 스코어 | −2147483648 … 2147483647 | 1 |
| `bool` | 스코어 (0 또는 1) | `false`, `true` | — |
| `Milli` | 스코어, 값 × 1000 | −2147483.648 … 2147483.647 | 0.001 |
| `Q16` | 스코어, 값 × 65536 | −32768 … 32767.99998 | 1/65536 |

7.1.1 `float`과 `double`은 각각 `Milli`, `Q16`의 옛 이름입니다. 같은 타입이며, 쓸 때마다 경고 진단이 나옵니다.

7.1.2 소수 리터럴은 가장 가까운 단위 값으로 반올림되어 저장됩니다 (`0.0005f` → 0.001, `0.0004f` → 0.000).

7.1.3 `Q16`의 단위는 2진 분수입니다. 따라서 `0.15`처럼 10진수로 끝나는 값은 정확히 표현되지 않습니다 (0.15 → 9830/65536 ≈ 0.1499939). 10진 소수를 정확히 다뤄야 하면 `Milli`를 써야 합니다.

### 7.2 문자열

7.2.1 `string`은 **컴파일 타임 상수만** 가집니다. 런타임에 값이 정해지는 `string`은 없습니다.

7.2.2 `NString`은 NBT 스토리지에 저장되는 런타임 문자열이며 **값 의미**를 가집니다 (대입은 복사).

7.2.3 `string`을 기대하는 자리에 `NString`을 넘기는 것은 타입 오류입니다. 이 규칙이 13.2.3의 기반입니다.

### 7.3 배열

7.3.1 `T[]` (`T`: `int`, `bool`, `Milli`, `Q16`)는 원소마다 스코어 하나를 씁니다. 길이는 컴파일 타임 상수이며 16384 이하여야 합니다.

7.3.2 상수 인덱스가 범위를 벗어나면 오류 진단입니다. 런타임 인덱스가 범위를 벗어나면 읽기는 0이고 쓰기는 무시됩니다.

7.3.3 `NArray<T>`는 스토리지에 저장되는 가변 길이 배열이며 **참조 의미**를 가집니다. 범위 밖을 읽은 결과는 0이거나 대상 변수를 바꾸지 않습니다. 둘 중 어느 쪽인지는 지정되지 않으므로, 프로그램은 `Length`로 먼저 확인하는 것이 좋습니다.

7.3.4 `static readonly` 배열은 **테이블**입니다. 원소는 컴파일 타임 상수이며 (13.4), 실행 중에 바뀌지 않습니다.

### 7.4 미설정 스코어

7.4.1 외부 스코어(3.6)가 미설정이면, 그 스코어를 읽는 모든 연산은 **0을 읽은 것과 같은 결과**를 내야 합니다. 대입, 산술, 비교(`==`, `!=`, `<`, `<=`, `>`, `>=`)가 모두 해당합니다.

  > 예: 엔티티 `e`에 `hp` 스코어가 없으면 `e.Hp == 0`은 참, `e.Hp != 0`은 거짓, `int x = e.Hp;` 뒤 `x`는 0입니다.

7.4.2 읽기는 스코어를 만들지 않습니다. 읽은 뒤에도 외부 스코어는 미설정으로 남습니다.

7.4.3 소유 홀더는 읽기 전에 항상 값이 있습니다 (C#의 확정 대입 규칙과 9.3).

## 8 연산

### 8.1 정수

8.1.1 `+`, `-`, `*`와 `++`, `--`, 복합 대입은 32비트 2의 보수로 감쌉니다 (overflow 시 wrap). `2147483647 + 1` → −2147483648.

8.1.2 `/`와 `%`는 기본적으로 C#과 같습니다: 몫은 0 쪽으로 버리고, 나머지는 피제수의 부호를 따릅니다. `-7 / 2` → −3, `-7 % 2` → −1.

8.1.3 `[MinecraftDivision]`이 붙은 메서드·클래스 안, 또는 `"division": "minecraft"`인 프로젝트에서는 `/`가 음의 무한대 쪽으로 버리고 `%`가 제수의 부호를 따릅니다. `-7 / 2` → −4, `-7 % 2` → 1. `[CSharpDivision]`은 이를 다시 8.1.2로 되돌립니다.

8.1.4 0으로 나누면 피제수가 **그대로 남습니다** (`x / 0` → `x`, `x % 0` → `x`). 예외는 없습니다.

### 8.2 Milli

8.2.1 `+`, `-`는 정확합니다. 결과가 7.1의 범위를 벗어나면 감쌉니다.

8.2.2 `a * b`의 결과는 실제 곱을 0.001 단위로 **음의 무한대 쪽으로 버린 값**입니다. 결과가 범위 안에 있으면 중간 계산에서 넘침이 일어나지 않아야 합니다.

8.2.3 `a / b`의 결과는 실제 몫을 0.001 단위로 **0 쪽으로 버린 값**입니다. `|b| ≤ 2147.483`이면 정확합니다. 그보다 크면 마지막 자리가 1만큼 다를 수 있습니다. `b == 0`이면 `a`가 그대로 남습니다.

8.2.4 상대가 정수값인 상수(`x * 2`, `x / 4`)면 구현은 명령 하나로 계산해야 합니다. 그 밖의 곱셈·나눗셈은 보조 함수(`<ns>:__math/mmul`, `mdiv`)를 호출합니다.

8.2.5 `(int)x`는 0 쪽으로 버립니다.

### 8.3 Q16

8.3.1 `a * b`는 1/65536 단위로 음의 무한대 쪽으로 버립니다. 결과가 범위 안에 있으면 정확합니다.

8.3.2 `a / b`는 1/65536 단위로 0 쪽으로 버립니다. 결과가 범위를 넘거나 `b == 0`이면 ±2147483647(원시값)로 포화합니다.

8.3.3 26.3 이상에서는 구현이 `/compute`를 쓸 수 있습니다. 결과는 8.3.1–8.3.2와 같아야 합니다.

### 8.4 변환

| 변환 | 결과 |
|---|---|
| `int` → `Milli`, `Q16` | 정확 (범위를 넘으면 감쌈) |
| `Milli`, `Q16` → `int` | 0 쪽으로 버림 |
| `Milli` ↔ `Q16` | 대상 단위로 음의 무한대 쪽으로 버림 (`(Milli)-0.0007` → −0.001) |

### 8.5 비교와 논리

8.5.1 비교는 수학적 값을 비교합니다. 외부 스코어에는 7.4가 적용됩니다.

8.5.2 `&&`, `||`, `?:`는 단락 평가합니다. 평가되지 않는 쪽의 명령(부작용 포함)은 실행되지 않습니다.

## 9 저장소, 이름, 수명

### 9.1 저장소

| 저장소 | 이름 |
|---|---|
| 기본 objective | `mcs.<ns>` |
| `[Score]` 필드의 기본 objective | `<ns>.<필드 이름의 snake_case>` |
| 이벤트 objective | `<ns>.ev.*` |
| 내부 스토리지 (`NString`, `NArray`, 테이블, 매크로 인자, 재귀 스택) | `<ns>:mcs` |
| `NbtLib.Storage` 기본 스토리지 | `<ns>:data` |

### 9.2 이름

9.2.1 다음 이름은 **안정**입니다. 같은 소스는 같은 이름을 내야 하며, 프로그램과 사람이 게임 안에서 이 이름으로 값을 읽어도 됩니다.

| 대상 | 홀더 (objective `mcs.<ns>`) |
|---|---|
| 최상위 정적 필드 `x` | `$static.x` |
| 클래스 안의 정적 필드 | `$static.<경로>.x`. `<경로>`는 네임스페이스와 바깥 클래스부터 차례로 snake_case, `.`으로 이음 |
| 정적 배열 원소 | `<필드 홀더>[i]` |
| 정적 객체의 필드 | `<필드 홀더>.<필드>` |

  > 예: `static class Lamps { public static class State { public static int lit; } }` → `$static.lamps.state.lit`

9.2.2 서로 다른 정적 필드는 서로 다른 홀더를 가져야 합니다. 이름이 같은 클래스가 다른 클래스 안에 중첩되어 있어도 마찬가지입니다.

9.2.3 메서드는 `/function <ns>:<m>`으로 부를 수 있습니다. 클래스 메서드는 `<ns>:<class>/<m>`입니다. 두 메서드의 경로가 겹치면 구현이 뒤에 `_`를 붙여 구분합니다. 이때 어느 쪽이 `_`를 받는지는 지정되지 않습니다.

9.2.4 지역 변수(`$<m>.<변수>`), 임시 값(`$<m>#t<n>`), 반환 값(`$<m>#ret`), 엔티티 변수 태그의 이름은 **참고용**입니다. 디버깅에 쓸 수 있지만, 구현이 바뀌면 달라질 수 있습니다.

9.2.5 `__`로 시작하는 식별자, 함수 경로 `<ns>:__*`, 태그 접두사 `mcs.<ns>.`는 구현이 예약합니다 (부속서 A).

### 9.3 수명

9.3.1 **정적 숫자 필드와 정적 배열**: 로드할 때 홀더가 미설정이면 초기값이 들어갑니다. 이미 값이 있으면 **그대로 둡니다**. 따라서 값은 `/reload`, 서버 재시작, 데이터팩 업데이트 뒤에도 유지됩니다.

9.3.2 9.3.1의 결과로, 소스의 초기값을 바꿔도 **이미 값이 있는 월드에는 반영되지 않습니다**. 로드할 때마다 값을 정하려면 `[Load]` 메서드에서 대입해야 합니다.

9.3.3 **정적 `NString`, `NArray`**: 로드할 때 스토리지 경로가 없을 때만 초기값이 들어갑니다 (9.3.1과 같은 규칙).

9.3.4 **정적 객체** (`static Vec v = new Vec(…)`): 생성자는 월드에서 처음 로드될 때 한 번만 실행됩니다.

9.3.5 **`const`와 테이블**: 컴파일 타임 값입니다. 테이블의 스토리지 사본은 로드할 때마다 다시 씁니다.

9.3.6 **지역 변수**: 메서드마다 고정된 홀더 하나입니다. 선언이 실행될 때마다 초기값이 들어갑니다. 같은 메서드가 `Wait()`로 멈춘 동안 다시 호출되면 두 실행이 지역 변수를 공유합니다. 재귀 호출에서는 10.7이 적용됩니다.

9.3.7 월드의 MC# 상태를 처음 상태로 되돌리려면 `/scoreboard objectives remove mcs.<ns>`와 `/data remove storage <ns>:mcs`를 실행한 뒤 `/reload`합니다.

## 10 실행 모델

### 10.1 로드 순서

10.1.1 로드할 때마다 다음 순서로 실행되어야 합니다.

1. objective 생성 (9.1)
2. 정적 필드 초기화 (9.3.1–9.3.4). **필드 사이의 순서는 지정되지 않습니다.** 한 정적 필드의 초기값이 다른 정적 필드의 값에 의존해서는 안 됩니다.
3. `[Load]` 메서드. 소스 순서 (6.1.2)
4. `Main()`

10.1.2 1.21.9 이상에서 프로그램이 월드 스폰 위치를 쓰거나 엔티티·블록을 만들면, 구현은 스폰 청크를 강제로 불러오고 그 청크가 불러와진 뒤에 `Main()`을 실행합니다. 이때 `Main()`은 로드보다 늦은 틱에 실행될 수 있습니다.

10.1.3 `Main()`과 `[Load]`는 `/reload`할 때마다 다시 실행됩니다.

### 10.2 기본 실행 맥락

10.2.1 로드, 틱, `/schedule`로 실행되는 코드의 실행 주체는 **서버**이고, 위치는 오버월드의 **월드 스폰**입니다. 이때 `@s`는 아무것도 선택하지 않습니다.

10.2.2 `Position.Here`는 현재 실행 맥락의 위치(`~ ~ ~`)입니다.

### 10.3 틱 순서

10.3.1 매 틱에 다음 순서로 실행되어야 합니다.

1. 이벤트 분배 함수 (`[OnJoin]` 등이 있을 때)
2. `[Tick]` 메서드. 소스 순서
3. 그 틱에 예정된 `/schedule` 함수 (`Wait()`의 나머지 포함)

10.3.2 한 메서드 안에서는 문장이 소스 순서대로 실행되며, 각 문장은 다음 문장이 시작하기 전에 끝납니다 (`Wait()` 제외, 10.5).

### 10.4 이벤트

10.4.1 이벤트 메서드는 이벤트가 일어난 플레이어마다 한 번, **그 플레이어로서(`@s`), 그 플레이어의 위치에서** 실행됩니다.

10.4.2 이벤트는 일어난 그 틱의 10.3.1 단계 1에서 처리됩니다. 한 이벤트에 메서드가 여럿이면 소스 순서로 실행됩니다.

### 10.5 Wait

10.5.1 `Wait(n)`은 현재 메서드를 멈추고, 나머지를 `n`틱 뒤에 `/schedule`로 실행합니다. **호출한 쪽은 기다리지 않고** 바로 다음 문장으로 넘어갑니다.

10.5.2 `Wait()` 뒤의 코드는 10.2.1의 기본 실행 맥락에서 실행됩니다. 실행 주체, 위치, `Player.Self`는 이어지지 않습니다. 엔티티 변수(태그), 정적 필드, 지역 숫자 변수는 이어집니다.

10.5.3 `Wait()`는 `switch`, `foreach`, 람다, `[Inline]` 메서드, 엔티티 인스턴스 메서드, 값을 반환하는 메서드, 재귀 메서드 안에서 쓸 수 없습니다 (오류 진단). `Wait()`가 들어 있는 반복문에서는 `break`, `continue`를 쓸 수 없습니다.

### 10.6 엔티티 맥락

10.6.1 `foreach (var e in Entities.All<T>(…))`의 본문은 선택된 엔티티마다 한 번, **그 엔티티로서** 실행됩니다. `at: true`이면 그 엔티티의 위치에서도 실행됩니다. 본문에서 `break`는 쓸 수 없습니다.

10.6.2 엔티티 클래스의 인스턴스 메서드는 그 엔티티로서, 그 엔티티의 위치에서 실행됩니다.

### 10.7 재귀

10.7.1 호출 그래프의 순환 안에 있는 호출은 호출자의 지역 변수, 매개변수, 임시 값을 `<ns>:mcs stack`에 저장했다가 호출 뒤 되돌립니다. 엔티티 매개변수(태그)는 저장되지 않습니다.

10.7.2 모든 호출은 같은 틱 안에서 실행됩니다. 한 틱의 명령 수가 `maxCommandChainLength`(기본 65536)를 넘으면 Minecraft가 남은 명령을 실행하지 않으며, 그때 프로그램 상태는 지정되지 않습니다.

## 11 문장

11.1 지원하는 문장: `if`/`else`, `while`, `do`-`while`, `for`, `foreach`, `switch`, `break`, `continue`, `return`, 식 문장, 지역 선언, `asm`.

11.2 `switch`는 정수와 열거형에만 쓸 수 있습니다. `break`는 섹션의 마지막 문장으로만 쓸 수 있습니다. 상수에 대한 `switch`는 맞는 섹션만 남깁니다.

11.3 `foreach`의 대상과 의미:

| 대상 | 의미 |
|---|---|
| `Entities.All<T>(…)` | 엔티티마다 그 엔티티로서 실행 (10.6) |
| `T[]` 배열 | 런타임 반복. `break`, `continue` 가능 |
| `NArray<T>` | 런타임 반복 |
| 테이블, `Unroll.Range(a, b)` | 컴파일 타임 전개 (13.4) |

## 12 클래스와 객체

12.1 일반 클래스와 구조체의 필드는 스코어로 펼쳐집니다. `NString`, `NArray` 필드는 스토리지에 있습니다.

12.2 객체 참조는 **컴파일 타임에 고정**됩니다. `Vec b = a;`는 `b`를 `a`와 같은 객체로 만듭니다. 실행 중의 조건에 따라 다른 객체를 가리키게 하는 대입은 오류 진단입니다. `null`은 없습니다.

12.3 객체 안의 객체 필드는 포함(embedding)됩니다. 클래스는 자기 자신의 타입을 필드로 가질 수 없습니다.

12.4 **되씀 규칙.** 인스턴스 메서드 호출 `o.M(…)`은 `o`를 메서드의 `this` 프레임으로 복사하고, 메서드가 `this`를 바꿀 **수 있으면** 호출 뒤 프레임을 `o`로 다시 복사해야 합니다. 다음 중 하나라도 메서드 본문에 있으면 바꿀 수 있는 것으로 봅니다.
  - 자기 필드에 대한 대입, `++`, `--`
  - 자기 `NArray` 필드의 원소 대입 또는 변경 메서드 호출 (`Add`, `Insert`, `RemoveAt`, `Pop`, `Clear`)
  - 자기 인스턴스 메서드, 또는 자기 객체 필드의 인스턴스 메서드 호출
  - `this`, 또는 객체·`NArray` 타입의 자기 필드를 다른 메서드의 인자로 넘기기

12.5 객체나 `NArray`를 인자로 받은 메서드가 그것을 바꾸면, 호출 뒤 호출자의 객체에 반영되어야 합니다.

12.6 가상 호출은 객체의 실제 클래스로부터 컴파일 타임에 결정됩니다.

12.7 `ToString()` 재정의는 식 하나(`=> $"…"`)여야 하며, 객체를 출력하는 자리에서 평가됩니다.

12.8 엔티티·블록·아이템 객체는 **한 번만** 소환·설치·지급할 수 있습니다. 같은 메서드 안에서 두 번 쓰면 오류 진단이고, 반복문처럼 실행 시점에만 알 수 있으면 두 번째부터는 실행되지 않고 메시지가 출력됩니다. `Clone()`으로 새 객체를 만들 수 있습니다.

## 13 컴파일 타임 평가

### 13.1 원칙

13.1.1 컴파일 타임 상수(3.9)로 결정되는 `if`, `switch`, `?:`, 반복은 번역 시점에 풀립니다. 선택되지 않은 쪽의 명령은 데이터팩에 들어가지 않습니다.

### 13.2 [Inline]

13.2.1 `[Inline]` 메서드는 함수가 되지 않습니다. 호출할 때마다 본문이 그 자리에 펼쳐집니다.

13.2.2 매개변수의 바인딩:

| 인자 | 매개변수의 값 |
|---|---|
| 컴파일 타임 상수 | 그 상수 (3.9 (b)). 본문의 분기와 보간이 번역 시점에 풀림 |
| 런타임 값 | 호출 시점에 한 번 평가되어 임시 스코어에 저장됨 |

13.2.3 `string` 매개변수의 인자는 항상 컴파일 타임 상수입니다 (7.2.1, 7.2.3). 따라서 `string` 매개변수가 `asm $"…"`에 들어가도 **매크로 줄이 되지 않습니다**. 1.20.1에서도 동작합니다.

13.2.4 `string` 매개변수를 가진 메서드는 `[Inline]`이어야 합니다.

13.2.5 `[Inline]` 메서드는 마지막 문장에서 값을 반환할 수 있으며, `string`, `Text`, `Button`도 반환할 수 있습니다.

### 13.3 명령 보간 (`asm $"…"`)

13.3.1 보간 구멍 `{식}`마다:

| 식 | 결과 |
|---|---|
| 컴파일 타임 상수 | 글자 그대로 끼워 넣음 (13.3.2) |
| 런타임 값 | 그 명령 전체가 매크로 줄이 됨 (1.20.2 이상) |

13.3.2 상수의 표기:

| 타입 | 표기 | 예 |
|---|---|---|
| `int` | 10진 정수 | `4` |
| `bool` | `true` / `false` | `true` |
| `Milli`, `Q16` 리터럴 | 리터럴의 10진 표기 | `0.37`, `0.15` |
| 계산된 `Milli` | 최대 소수 셋째 자리 | `0.75` |
| 계산된 `Q16` | 최대 소수 여덟째 자리 (7.1.3 참고) | `0.1499939` |
| `string` | 그대로 | `stone` |

13.3.3 런타임 `Milli`, `Q16` 값은 Java `double`의 10진 표기로 들어갑니다 (예: −0.205 → `-0.20500000000000002`). 이 표기는 Minecraft가 좌표와 회전으로 받아들이는 숫자입니다.

13.3.4 대상 범위에 1.20.2 미만이 있고 매크로 줄이 필요하면, 구현은 해당 버전을 밝힌 오류 진단을 내야 합니다 (4.3).

### 13.4 전개

13.4.1 `foreach (int i in Unroll.Range(a, b))`는 `i = a, a+1, …, b-1`마다 본문을 복사합니다. `a`, `b`는 컴파일 타임 상수여야 합니다.

13.4.2 테이블에 대한 `foreach`도 원소마다 본문을 복사하며, 반복 변수는 그 원소의 컴파일 타임 상수입니다.

13.4.3 테이블을 상수 인덱스로 읽으면 상수가 됩니다. 런타임 인덱스로 읽으면 스토리지와 매크로를 씁니다 (1.20.2 이상).

## 14 버전 대응

14.1 지원하는 대상 버전은 1.20.1 – 26.3입니다. 그 밖의 버전을 지정하면 오류 진단입니다.

14.2 각 팩 포맷 그룹의 첫 버전마다 `MC_<버전>_OR_GREATER` 기호가 정의됩니다 (`mcs --versions`). `#if`로 분기할 수 있습니다.

14.5 이 문서는 **MC# 언어 1.0**을 정합니다. 언어 버전은 `<주>.<부>`입니다. 부 버전이 오르면 기능이 추가되고 기존 적합 프로그램의 의미는 바뀌지 않습니다. 주 버전이 오를 때만 기존 프로그램의 의미가 바뀔 수 있습니다.

14.6 구현은 자신이 구현하는 언어 버전까지의 모든 버전에 대해 `MCS_<주>_<부>_OR_GREATER` 기호를 정의합니다 (1.0에서는 `MCS_1_0_OR_GREATER`). `mcs --version`이 언어 버전을 출력합니다.

14.7 `mcs.json`의 `"language"`(또는 `--language`)는 프로젝트가 요구하는 언어 버전입니다. 구현의 언어 버전보다 높으면 오류 진단입니다. 형식이 `<주>.<부>`가 아니어도 오류 진단입니다.

14.3 블록·아이템·엔티티·효과 ID는 각 대상 버전의 게임 데이터로 검사됩니다. 없는 ID는 해당 버전을 밝힌 오류 진단입니다. 이름이 바뀐 ID는 자동으로 대응됩니다.

14.4 `minecraft:` 이외의 네임스페이스 ID는 오류 진단입니다.

## 부속서 A (규정) 예약된 이름

다음은 구현이 쓰므로, 프로그램이 직접 만들거나 바꾸지 않아야 합니다.

- 식별자: `__`로 시작하는 이름, `__Global`
- objective: `mcs.<ns>`, `<ns>.ev.*`
- 스토리지: `<ns>:mcs` (프로그램은 `NbtLib`의 `<ns>:data`를 씁니다)
- 함수: `<ns>:__*` (`__load`, `__math/…`, `__events/…`, `__macro/…`, `__sinit/…`, `__arr/…`)
- 태그: `mcs.<ns>.*`
- 홀더: `$`로 시작하는 이름, `#<정수>`

## 부속서 B (참고) 라이브러리 호출의 실행 맥락

| 호출 | 누가 / 어디서 / 누구에게 |
|---|---|
| `m.Console.WriteLine(x)` | `tellraw @a`: 모든 플레이어에게 |
| `Sound.Play(id, pos, …)` | `pos`에서 재생, 범위 안의 모든 플레이어가 들음 |
| `Sound.PlayTo(players, id, …)` | `players`의 각 플레이어 위치에서, 그 플레이어만 들음 (`execute as <players> at @s run playsound … @s ~ ~ ~`) |
| `Sound.Stop(players[, id])` | `players`의 모든 소리 범주에서 정지 |
| 이벤트 메서드 | 그 플레이어로서, 그 플레이어 위치에서 (10.4) |
| `Wait()` 뒤 | 서버로서, 월드 스폰에서 (10.5.2) |
| `[Load]`, `[Tick]`, `Main()` | 서버로서, 월드 스폰에서 (10.2) |

각 멤버의 시그니처, 기본값, 열거형의 모든 값(`SoundSource` 등)은 [API 레퍼런스](../api.md)에 있습니다.

## 부속서 C (참고) 시뮬레이터로 확인할 수 있는 범위

`mcs run`은 데이터팩을 빌드한 뒤 Minecraft 없이 실행합니다 ([튜토리얼 8](tutorial/08-testing.md)).

| 확인할 수 있음 | 확인할 수 없음 (명령이 `> …`로 출력됨) |
|---|---|
| 스코어 (32비트 감쌈, 나눗셈 규칙), 스토리지, 매크로, `/compute` | 블록, 위치, 엔티티 NBT |
| 함수 호출 순서, `/schedule`, `#tick`, `#load`, `/reload` | 소리, 파티클, 효과 |
| `execute if/unless/as/store`, 셀렉터 (`type`, `tag`, `name`, `scores`, `limit`) | 몹의 행동 |
| 대본으로 만든 플레이어: 접속, 죽음, 통계, `/trigger`, 우클릭, 인벤토리 | 실제 플레이어 입력 |

시뮬레이터는 Minecraft가 거부할 명령을 `! <오류>`로 표시합니다. `--real` 테스트는 같은 데이터팩을 실제 서버에서 돌려, 시뮬레이터와 스코어가 다르면 실패합니다.

## 부속서 D (참고) 이 판에서 고친 결함

이 판과 함께 다음 결함을 고쳤습니다. 각 항목은 `tests/cases/regressions.mcs`로 검사합니다.

| # | 결함 | 이전 동작 | 관련 규칙 |
|---|---|---|---|
| D.1 | `Entities.Spawn`, `Merge`의 SNBT | 끝의 `}`를 **전부** 잘라 `{data:{a:1}}` → `{data:{a:1}` | — |
| D.2 | 인스턴스 메서드 안의 `NArray` 필드 변경 | `Items.Add(x)`, 도우미 메서드에 넘긴 변경이 객체에 반영되지 않음 | 12.4 |
| D.3 | 이름이 같은 중첩 클래스의 정적 필드 | `Lamps.State.lit`과 `Doors.State.lit`이 홀더 하나를 공유 | 9.2.2 |
| D.4 | 미설정 외부 스코어 읽기 | 대입은 이전 값을 유지, 비교는 `==0`과 `!=0`이 둘 다 거짓/참으로 어긋남 | 7.4 |
| D.5 | `Milli`의 `*`, `/` | 원시값을 먼저 곱해 약 2147을 넘으면 넘침 (`3000f * 2` → 1705.032) | 8.2 |
| D.6 | `[Inline]`의 상수 `Milli`/`Q16` 인자를 명령에 넣기 | 원시 스코어가 들어감 (`0.37f` → `370`) | 13.3.2 |

**이전 판에서 업그레이드할 때:** D.3으로 **중첩 클래스** 안 정적 필드의 홀더 이름이 바뀌었습니다 (예: `$static.state.lit` → `$static.lamps.state.lit`). 최상위 클래스의 정적 필드(`$static.a.lit`)와 최상위 필드(`$static.x`)는 그대로입니다. 기존 월드에서 이름이 바뀐 필드는 9.3.1에 따라 초기값으로 다시 시작합니다.
